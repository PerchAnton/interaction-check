# interaction-check 0.1.0b2 — release candidate

Not published. This maintenance candidate contains the Unicode console fix
already merged after 0.1.0b1; it does not add a new runner feature.

In 0.1.0b1, a Cyrillic scenario name can raise `UnicodeEncodeError` under ASCII
or Windows-1252 before the JSON report is saved. The candidate escapes only
unrepresentable console characters. JSON, JUnit and exported expectations retain
the original Unicode, and the existing pass/fail exit codes remain unchanged.
The quickstart adapter reads its JSONL input as UTF-8.

Qualification covers the installed wheel outside the checkout: ASCII, Windows-1252
and UTF-8, both a passing Unicode title and a deliberate mismatch, each requiring
a new JSON report. Existing source tests also cover Unicode protocol data and
export paths.

The jsonpatch 1.39 example keeps the published 0.1.0b1 check and separately tests
the candidate wheel against the same three scenarios / nine steps. These examples
verify replay behavior, not adoption, rendering or an advantage over native tests.

Before publication, review CI and verify the exact wheel/source archive checksums.
Publication requires a separate decision; no release is created by this PR.
